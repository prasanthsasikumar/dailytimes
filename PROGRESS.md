## Decisions (ambiguities resolved with the simplest reasonable option)
- **One token per device.** The same token is used by the assistant (MCP/webhook/email) and the device agent. Simpler to set up; a leaked token can at worst queue or mark briefs.
- **MCP auth** accepts `Authorization: Bearer` or `?token=` on the URL, because several connector UIs only take a URL. No OAuth in the MVP.
- **Registration** is open when `DAILYTIMES_ADMIN_TOKEN` is unset (local dev); otherwise it requires the admin token.
- **"Brief of the day"** is keyed by the device's local date (IANA timezone set at registration). Brief dates may be yesterday..+7 days; pending briefs for past dates expire on the next poll.
- **Newest wins**: a new brief for a date supersedes pending ones for that date; byte-identical content is a no-op (`duplicate`).
- **Dedup** works on items that have a source link (text/bullet/qr `url`), canonicalised (no www, no tracking params). History is written when the agent reports `printed`, not when queued, so same-day revisions don't dedup against each other. Items seen in the last 60 days are dropped and reported back as `dropped_duplicates`; headings left empty are pruned; if nothing is left the brief isn't queued (`empty_after_dedup`). Items without links (calendar rows, prices) are never deduped.
- **Validation**: unknown fields/types rejected; control characters rejected; newlines are only allowed in text/bullet/small (collapsed to spaces); urls must be absolute http(s) with a dotted host. Limits: 80 blocks, 6000 chars.
- **Inbound email** recipient is `brief+<token>@<domain>`; body is a JSON brief or markdown-ish text. The webhook MIME transport is implemented; IMAP is a stub.
- **MCP SDK** is mcp 2.x (`MCPServer`), stateless streamable HTTP with JSON responses, mounted at `/mcp` on the FastAPI app. The SDK's localhost-only DNS-rebinding guard is disabled because the relay runs behind a public hostname; every call is token-authenticated.
- **Fonts** are bundled (OFL): UnifrakturMaguntia for the nameplate, PT Serif/PT Sans/PT Sans Narrow for text, so output is identical on a Pi, a Mac and in Docker. Characters the fonts lack (emoji, arrows) are substituted (`→` -> `->`) or dropped rather than printed as boxes.
- **Layout** is measured in points with ReportLab's unhinted widths; the raster renderer paints the same ops at the profile dpi (1-bit, no anti-aliasing for mono profiles). QR codes are drawn as modules (vector rects in PDF, whole-pixel modules in raster) so they stay scannable.
- **Newspaper layout**: page 1 masthead (nameplate, double rule, date bar with Vol./No. = day of year), N columns with gutter rules, columns balanced on the last page, compact continuation header and "Page i of n" on later pages. A divider directly before a section heading is dropped (the heading has its own rule). Keep rules: headings stay with the next line, links with their item, no one-line widows/orphans.
- **Slip layout**: compact nameplate, inverted-bar section headings, dotted leaders on rows, centred QR.
- **Letter** profiles use US date order; everything else uses day-month-year.
- **Profiles** are looked up in `$DAILYTIMES_PROFILES`, `~/.config/dailytimes/profiles`, then the package. Shipped: thermal-58mm, thermal-80mm, a4, letter, plus a5 and receipt-80mm-pdf.
- **Adapters** declare the formats they accept; the caller renders for the printer's profile in that format (`adapters.print_brief`). Registry + `dailytimes.adapters` entry-point group, so a new printer type is one adapter class + one profile YAML (tested with a throwaway adapter).
- **CUPS/IPP**: `printer=` uses `lp` (PDF on stdin, `media=` from the profile, custom length for receipt PDFs). `uri=` sends an IPP/1.1 Print-Job with a small built-in encoder (no pycups/ipptool dependency). Printers that refuse PDF get a hint to add a driverless CUPS queue (`lpadmin … -m everywhere`). Discovery: `lpstat -v` + mDNS (`_ipp._tcp`, `_ipps._tcp`, and `_pdl-datastream._tcp` = raw 9100, suggested as ESC/POS).
- **ESC/POS** uses python-escpos `GS v 0` raster in 512-line fragments; cuts only if the profile has a cutter, otherwise feeds past the tear bar. Dry-run encodes into `escpos.printer.Dummy`.
- **Cat printers**: encoder implemented and tested; BLE transport is a stub (docs/cat-printers.md).
- **Email-to-print** sends the PDF over SMTP (STARTTLS, or implicit TLS on 465); `password_env` keeps secrets out of config.
- **Profile suggestion** is name/model heuristics (58/80 mm keywords, TM-/TSP/POS models); page printers get Letter in US/CA/MX/PH/... locales, A4 elsewhere.
- **Agent rules** (pure, in `agent/rules.py`): ignore if already printed today, before `print_after`, or within `cooldown_minutes` of the last attempt; otherwise print if a brief is waiting. With no brief: `retry` (default) waits for a later presence; `placeholder` prints a short "no brief yet" slip and `skip` silently closes the day, both only after `fallback_after`. A presence that gets past the gate counts as an attempt (starts the cooldown).
- **Agent state** (printed_on, last_attempt) lives in a JSON file, so a restart never double-prints; the relay also stops serving a brief once it's reported `printed`.
- **Multiple outputs** per agent (e.g. a receipt printer plus a PDF archive folder); the brief counts as printed if any output succeeds, and failures are reported to the relay as detail.
- **Agent timezone** defaults to the device timezone stored on the relay, so "today" means the same thing on both sides.
- **Relay outage**: the agent polls every `poll_interval_seconds` and caches today's brief, so it can still print from cache when the relay is unreachable at presence time.
- **Presence**: `manual` = local HTTP `POST /presence` (also used by `dailytimes presence`, phone shortcuts) plus optional GPIO push button; `gpio` = gpiozero `DigitalInputDevice` (PIR/mmWave OUT pin) with debounce and optional hold time; `simulated` = stdin/timer/code; `ble` = stub with bleak scanning and RSSI threshold (needs a stable advertiser, since phones randomise addresses).
- **Demo** picks free ports (8787 was taken on the dev machine) and binds to 127.0.0.1; it registers the device in the machine's timezone so the masthead shows your local date. The agent writes all four outputs from one presence event (four `file` outputs), which exercises the real relay → agent → render → adapter path rather than rendering separately.
- **Docker** packages only the relay (`.[relay]`), runs as non-root with SQLite on a volume, and publishes 8787 on localhost only, expecting a TLS reverse proxy in front.
- **SETUP_PROMPT.md** is assistant-agnostic: MCP connector first, webhook for shell-capable agents, email for the rest.

- **Full-page A4/Letter** (`fill_page: true` on a4, letter, a5): the layout picks the largest type scale in 0.85x-1.3x at which the brief fits exactly one page, by binary search over full layouts. Light briefs grow (capped so it never looks like large print); briefs that would spill a few lines are tightened back onto one page; longer ones keep normal size and paginate. Filling the page with *content* is the assistant's job: the tool description and SETUP_PROMPT now ask for 35-50 blocks on a page printer, 10-20 on receipts, with extra sections (weather, week ahead, papers, deadlines).
- **Samples are fictional** (Example Corp, example.com links, "Sample edition" title) so placeholder data can't be mistaken for real news or the user's own calendar. `examples/full_page_brief.json` is a 45-block full-page sample.

### Platform (M6–M7)
- **One Python app** serves the website, relay API, MCP and printer API, so there's one thing to deploy and one language to contribute in. Server-rendered Jinja pages with no client framework and no third-party scripts; fonts are served from the package.
- **Storage** goes through a deliberately small table API (`relay/db.py`) with two backends: SQLite for local/Docker, and Supabase via PostgREST over HTTPS for Vercel (serverless can't hold Postgres connections, and some Supabase setups don't expose Postgres publicly). Queue logic stays in Python, the same for both backends; the few multi-step writes aren't transactional, which is harmless at this scale (worst case: two pending briefs, and the newest is served). The store tests run against both, via `scripts/test_postgrest.sh` (real Postgres 17 + PostgREST 16.5 + Supabase roles).
- **Tables are prefixed `dt_` in `public`**, the simplest thing that works on any Supabase project, including a shared one, without server config changes. RLS is on with no policies; only the service key reads or writes.
- **Accounts own editions; printers own receipts.** One edition per user per day, newest wins; each printer prints it at most once per local day. Dedup history is per user and recorded when any printer prints.
- **Tokens split by capability**: a write-only *endpoint token* (`dts_`) for AI agents, put in the URL path (`/u/<token>/mcp`, `/u/<token>/brief`) because connector UIs often accept only a URL; *printer tokens* (`dtd_`) can only read today's edition and report status. Both are stored as SHA-256 hashes and shown once. This replaces M1's single token per device.
- **Sign-in is our own email magic link** (not Supabase Auth), so self-hosters need no Supabase at all and the browser never talks to the database. Links are single use, 15 minutes, rate-limited, and need a button press (mail scanners prefetch links). Sessions are HMAC-signed cookies with a per-user epoch for "sign out everywhere"; forms carry CSRF tokens. Mail goes via the Resend API, SMTP, or the log (dev).
- **Pairing**: 8-character codes from an unambiguous alphabet, 15 minutes, single use; `dailytimes setup` redeems one, discovers printers, picks a profile, test-prints and writes a mode-600 config. `dailytimes service` prints the systemd/launchd file for the machine.
- **Auto edition** is deterministic: headlines, titles and numbers exactly as published by keyless public sources (Google News RSS search, Hacker News Algolia, Reddit RSS, arXiv, Yahoo Finance chart API, Open-Meteo, user feeds). No LLM writes text, so nothing can be invented. Sources share the page fairly (32 linked items for a page, 12 for a slip), already-printed links are skipped, and a failing source just drops its section. Reddit's JSON API returns 403 to servers, so the RSS feed is used; Stooq is blocked, so Yahoo is used for quotes.
- **When the auto edition is built**: lazily, the first time a printer, the dashboard or the daily cron asks after the user's `auto_after` time, only if no AI sent one, and at most once per day (the day is claimed before fetching). An AI edition arriving later still wins, unless a printer already printed that day.
- **Interest suggestion** is a keyword heuristic by default (the text never leaves the server), with acronym expansion (HCI -> human-computer interaction, after "HCI" matched an insurer). If the operator sets `ANTHROPIC_API_KEY`, Claude (`claude-opus-5-5`, low effort, server-side refusal fallback) proposes sources instead, and the page says so. Either way the user reviews and edits.
- **User feed URLs are fetched with SSRF protection** (public IPs only, re-checked on each redirect, size/time caps). Known gap: DNS-rebinding race, documented in PRIVACY.md.
- **MCP is built per request** (fresh stateless server and session manager), because serverless hosts may not run ASGI lifespan events, which the SDK's session manager depends on.
- **Vercel quirks found on deploy**: it installs from `pyproject.toml` (not `requirements.txt`), so the server deps became core dependencies; its rewrite hands the function `/api/index` and drops the original path, so the rewrite passes it as `?__path=` and `api/index.py` restores it; new Supabase `sb_secret_` keys must go in the `apikey` header only; new Supabase projects grant nothing to API roles, so `schema.sql` grants `service_role` explicitly.
- **Vercel**: `api/index.py` + `vercel.json` (all routes to one function, `includeFiles: src/**`, a daily cron, which is the Hobby limit and enough since editions build on demand). The app refuses to start on Vercel without Supabase or without `DAILYTIMES_SECRET` (a random per-instance secret would sign people out on every cold start).
- **Endpoint at sign-up, shown again**: the website's endpoint tokens are HMAC(`DAILYTIMES_SECRET`, user id, generation), so the connect page can show the real link (and the Claude Code/Codex/Gemini commands with it filled in) on every visit while the database still holds only the hash. No schema change: the current generation is found by trying 0..999 against the stored hash. Older random tokens can't be shown; the page offers a new link. Changing the secret makes links unshowable (they keep working). CLI registration still uses random tokens.
- **Onboarding is AI-first**: sign-up lands on Connect AI with per-assistant tabs (Claude, ChatGPT, Gemini, Claude Code with `--scope user` + restart, Codex, other, none). The setup prompt has the AI call the `set_interests` MCP tool with what it knows about the user; interests record `set_by` (ai/you), the page polls `/app/connect/status` to show when interests and the first edition arrive. Describing yourself is now the fallback for people without an AI.
- **Retention**: editions and receipts 30 days, seen-link history 60 days, codes/links minutes; purged at most hourly on writes and by the daily cron.
